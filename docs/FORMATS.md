# 格式、数据结构与精度

[English](FORMATS.en.md) · [首页](../README.md)

## 输入与输出矩阵

| 数据类型 | 输入 / 生成 NCAE | GUI 源文件转 WAV | 后端其他格式互转 |
|---|---|---|---|
| WAV / WAVE、兼容 IRS | 支持 | 支持 | 支持 |
| FLAC、AIFF / AIF、AU / SND、CAF、W64、RF64 | 支持后端可解码的子类型 | 支持 | 支持容器允许的编码 |
| `ir.samples.v1` JSON / NPZ | 按采样数据生成 IR 载荷 | 支持 | 支持 |
| 参数 JSON | 按参数载荷处理，客户端语义需兼容 | 不支持 | 不能直接视作音频 |
| NCAE | 作为目标模板或待导出音效 | IR 载荷可导出 | 先解密后按载荷类型处理 |
| MP3、AAC、OGG、私有加密 IRS、任意其他 EQ 预设 | 不作为承诺支持的导入格式 | 不承诺 | 需要明确适配，不靠改后缀 |

NCAE 是容器；IR 与参数 JSON 是不同载荷。生成基于所选模板，不是无模板创建任意客户端资源。GUI 没有通用“输出 FLAC/AIFF”选择器，源码后端的通用互转能力与 GUI 功能应区分。

## `ir.samples.v1` JSON 示例

```json
{
  "schema": "ir.samples.v1",
  "sample_rate": 48000,
  "source_subtype": "DOUBLE",
  "samples": [[0.0, 0.0], [0.25, -0.25], [0.0, 0.0]]
}
```

`samples` 是 `[帧, 声道]` 二维数组，采样率为正整数，数据必须非空且全部有限。NPZ 保存同名 `schema`、`sample_rate`、`source_subtype`、`samples` 字段，读取时禁止 pickle。未知 `ir.samples.*` schema 被拒绝，不冒充参数预设。

## IRS 的含义

已适配可解析为 RIFF/WAVE 或后端支持音频的 IRS。本项目写出的 IRS 是使用 `.irs` 后缀的 WAV 容器，不是厂商专有加密格式。损坏或私有 IRS 不会作为不透明音频悄悄封装。

## 精度和处理

- 音频生成 NCAE 时标准化为 float32 WAV，float64 / 高精度整数转入可能量化。
- 源文件转 WAV 尽可能沿用源编码；显式子类型由后端转换命令指定。
- 原生 WAV 路径处理 PCM16 / PCM24 / PCM32 / float32；其他支持编码由后端处理。
- 转整数 PCM 需要合法范围；不悄悄缩放越界值。有效编码与容器组合由后端检查。
- 不自动重采样。长度选项只裁剪或补零，声道设置按使用说明处理。
- 通用转换后端保留采样率、帧数和声道顺序，不执行 EQ、混响或 DSP 渲染。
- 等价采样值的测试不代表所有容器的元数据、原始压缩字节或任意精度都无损保留。

## 防护边界

转换桥限制 1–8 声道、最多 16,777,216 个采样点；JSON 文件上限 128 MiB，NPZ 声明解压大小上限 256 MiB。预览另有独立的文件大小、帧数、JSON 深度/节点及 NCAE 解压上限，不把转换桥阈值当作全部解析器的统一保证。

拒绝非有限值、非法采样率、损坏容器或未知采样 schema。限制不是针对任意恶意文件的完整安全沙箱。

## 预览解释

IR 使用完整脉冲响应的 FFT，而非只取开头一段；声道、平滑和归一化仅影响显示。JSON EQ/PEQ 提供设置和已确认模型参考；混响、旋转等整套响应不由参数页伪造。数字 PEQ 类型不赋予未经确认的滤波器语义。
